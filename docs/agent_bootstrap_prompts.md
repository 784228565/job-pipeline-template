# AI Agent 引导 Prompt（复制即用）

本文档提供两段引导 prompt：一段给 **Kimi Code**（交互式 CLI agent），一段给 **WorkBuddy**（定时自动化 agent）。新用户把对应段落原样发给 agent，agent 即可完成"安装 → 信息采集 → 校验 → 产物生成"全过程。

两段 prompt 的共同设计原则：

- **信息采集不足禁止落地运行**——所有必填项必须由用户亲口提供，agent 不得编造、不得用默认值静默填充（默认值只作为用户回车跳过的兜底，且要在报告中声明）；
- **每步执行后回显产物路径与校验结果**，失败时原文返回错误、给出修复建议，不擅自绕过；
- **个人数据只写本机、绝不提交**（.gitignore 已兜底，prompt 中再显式禁止一次）。

## 1. 给 Kimi Code 的引导 Prompt

> 使用方式：在 Kimi Code 中新开会话，替换 `<你的GitHub用户名>` 后整段粘贴。

```
帮我从 GitHub 安装并配置求职投递管道项目。

## 任务目标
把 https://github.com/<你的GitHub用户名>/job-pipeline-template 克隆到本机，
完成新用户接入（画像创建 + 校验 + 个人版 prompt 生成），并把部署清单交给我。

## 执行流程（严格按序，每步完成后向我汇报结果再进行下一步）

### Phase 0：获取前置信息（必须先做，缺一项都问我）
在执行任何命令前，先向我收集以下信息。逐条提问，一次问 3-4 条，我答完再续。
【必填】
1. 中文名 / 英文名（名 姓）
2. 邮箱 / 手机号（大陆 11 位）
3. 现居城市 / 可到岗时间
4. 简历 PDF 在本机的完整路径
5. 教育经历（学历[本科/硕士/博士]、学校、专业、起止年份、状态[已毕业/在读/肄业]，可多条）
6. 届次身份一句话（必须含 "20XX届"，如 "2026届应届（毕业2年内、未缴社保）"）
7. 是否缴纳过社保（从未缴纳/缴纳过）
8. 核心技能（≥3 个，英文为佳）
9. 目标行业 / 求职方向
10. 目标就业城市
11. 正式工作年限（数字，应届填 0）
12. 目标公司国籍规则（如 "美/欧/中大型企业，排除日企韩企"，不限则填"不限"）
13. 海外岗位规则（不考虑海外填"无海外方向需求"；考虑则写明国家/地区与签证需求，如 "新加坡：需雇主担保 EP 签证"）
【选填】语言、论文、GitHub/作品集/LinkedIn、期望薪资口径——问一句即可，我跳过就不填。
⚠️ 禁止替我编造任何一项；我提供的值原样使用，不擅自"修正"。

### Phase 1：安装
1. git clone 仓库到本机合适目录并进入；
2. 通读 README.md 与 docs/prompts_template.md 的附A/附B，向我用 5 句话复述你理解的管道结构与我需要人工改写的 3 处结构性段落，等我确认理解无误再继续（发现理解偏差我纠正你）。

### Phase 2：接入
1. 把我的回答写入本地 answers.json（不要提交 git）；
2. 运行 python setup/onboard.py --answers answers.json；
3. 若校验失败：把每条拦截原因原文转达给我，我修改后重跑，直至输出"画像创建并校验通过"。

### Phase 3：生成产物
1. 运行 python setup/apply_tokens.py，确认输出"零残留占位符"；
2. 运行 python tests/run_tests.py，确认 5/5 通过；
3. 打开 build/prompts_personalized.md，把其中 5 段 prompt 分别对应调度器的 5 个定时任务位置告诉我，并列出每个任务的建议调度时间（06:00/11:37/12:30/13:00/15:00）。

### Phase 4：交付部署清单
最后给我一份清单：
- 我需要在调度器里粘贴的 5 段 prompt 所在文件与行号范围；
- 3 处必须人工改写的结构性段落（附A 清单）逐条说明改什么；
- CDP 环境前置条件（Chrome 启动参数、9222 端口、各平台登录）的验收方法；
- 换简历后的标准操作（重跑 onboard.py）。

## 禁止事项
- 禁止 git add/commit/push 任何包含我个人数据的文件（contracts/candidate_profile.json、local_tokens.json、build/、answers.json）；
- 禁止跳过校验器直接手改画像 JSON 绕过报错；
- 禁止在报告中隐去任何错误。
```

## 2. 给 WorkBuddy 的引导 Prompt

> 使用方式：在 WorkBuddy 中新建一条**一次性** automation（非定时），粘贴以下内容。运行后它会产出画像与 token 文件；之后把 `build/prompts_personalized.md` 中的 5 段 prompt 分别建为 5 条每日定时 automation（时间见文末）。

```
你是求职投递管道的安装向导。工作目录：<仓库克隆后的本地路径>。

## 你的任务
引导用户完成新用户接入，产出 contracts/candidate_profile.json 与 local_tokens.json 并校验通过。
本任务是一次性任务，产出后向用户报告部署步骤即结束。

## 第一步：信息采集（最重要，信息不全不许进入下一步）
用问答方式向用户收集以下必填项（逐项确认，允许用户一次回复多条）：
中文名、英文名(名 姓)、邮箱、手机号(大陆11位)、现居城市、可到岗时间、
简历PDF完整路径、教育经历(学历层级1本科/2硕士/3博士、学校、专业、起止、状态)、
届次身份(含20XX届)、社保缴纳情况(从未缴纳/缴纳过)、核心技能(≥3)、
目标行业、求职方向、目标就业城市、正式工作年限(数字)、
公司国籍规则、海外岗位规则。
选填项只问一轮：国籍/语言/论文/GitHub/作品集/LinkedIn/期望薪资，跳过即不填。
规则：不得替用户编造任何信息；用户给什么用什么。

## 第二步：执行
1. 将答案写入本地 answers.json（勿提交）；
2. 执行 python setup/onboard.py --answers answers.json；
3. 校验失败时，把拦截原因逐条反馈给用户，修改后重跑，直到通过；
4. 执行 python setup/apply_tokens.py 与 python tests/run_tests.py，确认零残留占位符、5/5 通过。

## 第三步：交付报告（必须包含）
- 画像与 token 文件路径、校验通过证明；
- 提醒用户：把 build/prompts_personalized.md 中 5 段 prompt 分别创建为每日定时 automation，
  调度时间依次为 06:00（搜索）/ 11:37（筛选）/ 12:30（预检）/ 13:00（投递）/ 15:00（通知）；
- 提醒用户按 docs/prompts_template.md 附A 人工改写 3 处结构性段落；
- 提醒 CDP 前置：chrome.exe --remote-debugging-port=9222 启动、投递平台已登录；
- 提醒：以上含个人数据的文件已被 .gitignore 排除，永远不会被提交。

## 禁止事项
禁止提交任何个人数据文件到 git；禁止绕过校验器；禁止对用户的必填信息使用默认值而不告知。
```

## 3. 为什么是"先收集、后落地"

两段 prompt 都强制 **Phase 0 信息采集 → Phase 1+ 执行** 的顺序，原因：

1. **校验器在收集侧和契约侧各挡一次**（onboard.py 收集时拒非法手机号/URL，validate_profile.py 拒非法学历/届次/hash），但错误最好发生在用户刚答完题、上下文还在的时候；
2. LLM agent 在"边想边问"模式下容易用合理默认值悄悄填空——显式禁止后，报告里出现的每个值都可追溯到用户原话；
3. 信息采集完成即固化成 `answers.json`，后续重跑/迁移/排查都有据可查。
